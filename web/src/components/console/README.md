# `components/console`

The console's own UI, built from `@ratel/design-system` primitives. Product-specific, so it stays
here rather than in the design system.

| Path | Holds |
|---|---|
| `shell/` | the inverted-L frame (DESIGN.md, Layout): `AppFrame` (rail, mobile drawer, ⌘K, `[` and `?`, and the edition's `ConsoleOverlays` after the shortcuts dialog), `Sidebar` (each rail item and the search carry a `data-tour` anchor for the guided tour), `ProjectSwitcher`, `AccountMenu` (the profile photo when the session has one, else initials; the edition's `AccountMenuItems` above the docs and the shortcuts, its optional `AccountMenuEndItems` after them), `CommandMenu` (pages, projects and the actions, reported as `command_palette_used` through the browser analytics seam: the edition's `commandActions` first, then Keyboard shortcuts and Collapse sidebar, built by `lib/console/command-actions.ts`), `ShortcutsDialog`, `AnalysisFreshness` (the "Analysis updated … ago" line at the rail foot inside a project), `ConsoleFrame` (the edition's banner and access gate around the shell, used by the console layout and by `/` for the states it shows), `DatabaseUnavailable`, `ShellSkeleton` (upstream's, a copy: the console layout's Suspense fallback, so a hard load draws the rail), `RememberProject` (asks the server to write the last-project cookie when a project page opens). The shell gets every organization the reader belongs to and their projects, and shows the one `shellOrganization` picks, with the edition's hidden organization pages for that one |
| `settings/` | project Settings: General (name; Model pricing, a project's own prices per model, admins only (`ModelPricingSection`, `ModelPricingTable`, copies; the actions are `lib/console/model-pricing/actions.ts`); the session replay content opt-in), API keys (create with an access choice, `ApiKeyAccessPicker`: Full, read-only, ingest-only or custom scopes; revoke; then `SdkQuickstart`: the "Send a trace" install line and snippets for this deployment), Developer (SDK events, undelivered events), Danger zone (delete). In an admin support session, creating and revoking keys and deleting the project are shown disabled (`restricted`) |
| `org/` | the organization's pages: Projects (list, the New project button, which opens `/onboarding` for the organization), Integrations (`IntegrationsPage`, `McpConnect`, `McpExample`: connect an MCP client to `/api/mcp`, with a browser sign-in for Claude Code, Claude Desktop and Cursor when the edition supplies `mcpOAuth`, else with a project key; the worked example and the tool groups) Settings > General (name, address) and Settings > Models (`ModelSettings`, `ModelCheckPanel`: the deployment's models, read-only, each feature's last failure, a Check now button; the open-source edition's); `OrgSkeleton`, an organization page's loading skeleton in its own shape (upstream's, a copy; the MCP page's `loading.tsx` draws its integrations variant) |
| `traces/` | the Traces pages: Runs (volume, stats, run panel; with the property filter bar `TraceFilterBar` on Sessions and Turns, matched on the trace rollup), Spans (list or grouped), Logs, one trace (timeline, conversation, details, ranking), and one turn call by call (`TurnDetailView`, the call an Agent health example is about ringed and scrolled to; `TurnLinkedPanel` for an SDK run's linked model calls); `compare/` holds the trace comparison, unchanged from the Cloud app |
| `errors/` | the 404 (`BrandedNotFound`, the searching badger) and its one link back, and the way back to a project's traces |
| `badgers/` | the honey-badger illustrations from `public/badgers/`, with the badger mark as the fallback when a file is missing |
| `onboarding/` | the first-project screen's parts: the backdrop (static dot-field; upstream's WebGL field is not carried), the emblem (the badger mark in place of upstream's dot-matrix orb), "What Ratel will read" (`CaptureConsentPanel`, a copy) and the send-your-first-trace snippet (`SdkQuickstart`, on the design system's `CodeBlock`, with the open-source OTel exporter) Also the guided tour: `GuidedTour` (the spotlight and its card) and `TourLauncher` ("Take the tour" in the Overview header; it starts by itself for someone who has never finished it), both upstream's. |
| `catalog/` | the Catalog pages: the tree of tools and skills, Tools, Skills, the item detail, and the skill editor (rebuilt on the design system); `CatalogSkeleton`, the explorer's and the tables' loading skeleton (upstream's, a copy, drawn by the three catalog routes' `loading.tsx`) |
| `playground/` | Test a search: a prompt ranked against the live catalog, with what-if edits to descriptions (rebuilt on the design system) |
| `health/` | Agent health's Summary (`v2/`: the state block, readings, turn shapes, issues with their fix leads and example turns, the self-corrections row, tasks that need a look, call order, unserved asks, the window switch and the menu: import, the PDF report, share, and the `HealthScore` ring that leads the Summary with `Calculating` while a reading is early), `share/open-share` (the event that opens the edition's share dialog), the public read-only page behind a share link (upstream's v1 `HealthPageView` and the cards, flow map, turn shapes, workflows and signal list it draws, with `surface` dropping every link into the project; `share/SharedPageActions`: Download PDF and Copy link; `primitives/`: upstream's button, tooltip, sparkline and match-quality tier styles that page draws with), the tool journey it draws, the setup callout and guide, and `report/` (the printable member report). Owned: `v2/SummaryView`, `v2/SummaryMenu`, `v2/HealthStateV2`, `v2/WindowSwitch` (a plan is named and "See plans" links to Billing only when billing is self-serve; the importer and the share dialog are the edition's slots), `v2/IssuesSection` and `v2/IssueExamples` (the lock on what the limits hide names no plan), `capture-nudge-model` and `HealthHeader` (a locked window's plan is named through the entitlements port) |
| `health/v2/PartialReading.tsx`, `InferredToolsCallout.tsx` | Agent health for imported runs with no tool calls (what the spans still say, and how to send tool calls), and the Ready page's note when most tool calls were inferred from span shape; copies |
| `tasks/` | Agent health › Tasks: the table, one task (steps, panels, flow diagram, sections), a session turn by turn, the skeletons |
| `self-corrections/` | Agent health › Self-corrections: the hero, where it happens, what the agent said, the change to make, filters and the examples read on demand |
| `fixes/` | Improvements › Fixes: the header and filters, one table per thing you do, a fix's panel with Mark as shipped (`MarkShippedButton`), and the kind icons the fix leads and marks share |
| `home/` | the Overview, a project's home: the four numbers with their days (`overview-stats`), the product at a glance, what needs attention, recent runs, the context breakdown and its panel, the setup guide shown until the first event, and the skeleton. Owned: `OverviewPage.tsx` (the setup guide's ingest address comes from `BASE_URL`, as onboarding's does). The header carries the guided tour's launcher, which records nothing in an admin support session. |
| `quality/` | Quality: the header with its window and analysis menu, Misses, Descriptions (rewrites to review, apply or dismiss) and Experiments; `report/` is the printable partner report (`ReportDocument`, the print button, and the quality charts, panels, theme and stylesheet upstream keeps beside its admin console). Owned: `report/panels.tsx` (a confidential name in a comment, replaced) and `report/format.ts` (the four admin-console formatters the report and the operator pages use; the admin console itself is excluded). `admin/` holds what only the operator's Quality pages draw: `Disclosure` and `SegmentedControl` (copies) and `primitives.tsx` (owned: the admin console's `PageHeader`, `Section` and `Card`) |
| `calibration/` | Quality › Experiments › an experiment's calibration: the arm role mix, agreement KPI band, latency and outcome panel, the comparison browser and its rows (the comparison page comes from the route's server action), the census tiles and the ranking diff of one selection; the generic experiment detail's arm grid, findings, lifecycle, conversion and capability rank diff panels; and the date-range control, route skeleton, delta chip and experiment badge upstream keeps beside its dashboard and trace components. All copies, unchanged from the Cloud app |
| `adaptive-ranking/` | Adaptive ranking: whether the graph is served, the with-and-without chart, how far it has learned, its setup steps and details, and its warnings (`RankingWarnings.tsx`: the gone tools, short and closable, with `rankingCatalogDrift`) |
| `intents/` | the Intents pages: All intents (the table, an intent's panel with its breakdown, steps, sentiment and examples), Flows (the canvas and step panel) and Map (the lens views), the skeletons, the states before a reading and "Read now"; all copies, the adaptive-ranking graph picker left out |
| `session-replay/` | the session page's parts: `SessionTimeline` (steps, context bars, decision chips, the message text the content opt-in allows), `WhatIfPanel` (fork a model call with a change, read the before and after, add the run to its task's eval set), `ContextLens`, `DecisionChip`, and `ContentOptIn` / `ContentOptInSection` for Settings › General |
| `session-chat/` | the session page as a chat, all copies: `SessionChatView` (each turn's ask, work line and reply over the time-scaled `SessionTrack`, with playback and "Next problem"), `SessionChatPanel` (the side panel a `?peek=` opens), `StepInspector` (one model call's context in sections, what changed since the call before, a tool step's arguments and result; text only with the content opt-in), `SessionTraceView` (a turn's full trace waterfall) |
| `traces-sessions/` | the Sessions list (`SessionListPage`, `SessionListView`, paged by cursor) and each tab's own summary (`TabSummary`, `MiniVolume`); copies, except `SessionListPage` (the project comes from the console scope) |
| `stale-build-callout.tsx` | the callout a stale server action shows: this tab is from before a deploy, reload |
| `agents/` | Traces › Agents behind `agentsPages` (the approved RP-25 design): `AgentsView` (the KPI band, the filter row with "Hidden (n)" for admins, the table nested by handoff that a column sort flattens, and `AgentHandoffMap`, the left-to-right map), `AgentDetailView` (role and status chips, the KPIs with "view failures", the flow strip, the tools grouped by MCP server), `AgentEditMenu` (the admin's Edit agent menu around upstream's `AgentOverrideControls`, owned), and what both entity pages share: `EntityFilters` (search, environment, the window) and `EntityParts` (trend, share bar, error pill, status chip) |
| `mcp-servers/` | Traces › MCP servers behind `agentsPages` (the approved RP-25 design): `McpServersView` (the KPI band, search and status filters, the status column, failing first) and `McpServerDetailView` (status chip, KPIs, tools by errors with their top error and callers, calling agents, recent errors) |
| `intent-map/` | the Map's drawing: intents as blobs, the asks pack, the tool network and globe, their chrome, marks, labels and measurements; all copies |

The navigation model behind the rail is `lib/console/navigation.ts`. Copies and owned files are
listed in `scripts/platform-sync/map.json`.
